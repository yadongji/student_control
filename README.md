# 学生综合管理系统（Windows 便携版）

## 新电脑 / 新班级

下载或克隆项目，将 `dist` 文件夹放到该班级独立的、可写入的目录中。

- 双击 `dist/学生综合管理系统.exe` 选择功能。
- `dist/01_直接打开教室系统.cmd` 直接打开教室系统。
- `dist/02_直接打开周末系统.cmd` 直接打开周末系统。
- 不需要安装 Python、MySQL 或其他运行环境。字体、系统托盘等使用 Windows 功能。
- 新目录没有班级数据时，程序以空名单启动；在软件中导入本班座次表，不会带入其他班级名单。
- 吉祥物等运行资源已打包进 EXE，无需复制旧版散落的素材文件夹。

每个班级使用独立目录。相同目录内重复打开同一入口会唤回现有窗口；不同目录的数据互不覆盖。

## 日常关闭 / 真正退出

主窗口右上角叉号隐藏到右下角托盘。单击托盘图标或再次打开原 CMD 可恢复；右键对应图标选择“退出”才真正结束。更新程序前请通过托盘退出。

详见 [托盘与启动使用说明](dist/托盘与启动使用说明.md) 和 [错题管理使用说明](dist/错题管理使用说明.md)。

## 数据只保存在本班电脑，不通过 Git 同步

以下文件/目录在 EXE 同目录中使用，但不纳入版本控制：

| 本地内容 | 用途 |
| --- | --- |
| `seat_data.json` | 座位、名单、纪律、请假、成绩、早读等班级记录 |
| `student_data.json` | 周末留校、留宿等记录 |
| `wrongbook/` | 错题数据库、学生关联与复习进度、图片和原始 Word |
| `evidence/` | 行为记录的图片证据 |
| `voice_settings.json` | 本机语音配置，可能含 API 密钥 |
| `backups/`、`*_backups/` | 各功能的本地备份 |

`dist` 采用发布文件白名单：只提交 EXE、两个 CMD、成绩导入模板和指定说明文件。新生成的数据文件默认忽略。不要使用 `git add -f` 强行提交本班数据，也不要使用 `git clean -fdx`，它会删除被忽略的数据。

## 已有电脑首次更新：务必先备份

旧版本曾跟踪 `dist/seat_data.json` 和 `dist/student_data.json`，本次取消跟踪。**其他旧克隆第一次拉取这次提交时，Git 可能删除未修改的旧数据文件；若本地有修改，也可能阻止拉取。**

1. 通过托盘退出程序。
2. 将该电脑的整个 `dist` 复制到仓库外的独立备份目录，确认两个 JSON、`wrongbook`、`evidence` 等本班数据齐全。
3. 推荐把新版克隆/解压到新目录，再从第 2 步的本班备份复制数据到新版 `dist`；不要复制其他班级的数据。
4. 如果选择在旧克隆上执行 `git pull`，必须先完成第 2 步。发生冲突时不要强制重置；更新完成后再把本班数据复制回原路径。
5. 打开新版，核对名单、纪律记录和错题数量，再继续使用。备份不要立即删除。

本次操作保留当前电脑的本地数据。移除跟踪不等于清除 Git 历史：过去提交中的名单仍可能从历史版本访问；本轮不重写历史、不强制推送。

## 后续更新 / 换电脑

完成首次迁移后，更新只替换程序和说明，不覆盖被忽略的班级数据。换电脑且需要保留同一班级时，应在退出后单独复制该班级数据；仅克隆代码仓库不会同步这些记录。错题管理也提供独立备份功能。

当前发布包含：Word 题目/解析导入、答案汇总表核对、学生关联拼音排序、全选/取消全选、托盘与重复启动唤回。仓库延续 EXE 分发结构，不包含开发过程的测试截图、临时题库或真实作业文档。
